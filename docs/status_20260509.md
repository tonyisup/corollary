## M4 Self-Voice Detection

- **Integration:** M4 detector wired into streaming runtime with frame-level metadata
  (m4_outcome, m4_confidence, m4_buffer_length)
- **F1 benchmark harness:** `scripts/m4_f1_benchmark.py` — deterministic, no hardware
  - 8 synthetic test cases (self_only, world_only, overlap, same_domain_negative, same-domain playback-window negative, room-colored self, device-EQ self, silence_gap)
  - Mock mode (pipeline verify) and --real-ecapa mode (promotion-grade)
  - Mock mode exits on pipeline acceptance; `--real-ecapa` exits on F1 acceptance; `--m4-min-buffer-ms` exposes warmup/latency tradeoff
- **Unit tests:** M4 tests cover SelfVoiceDetector + M4 attributor integration + expanded benchmark coverage + replay mode tests + mock pipeline acceptance semantics + clean-capture/capture-validation artifact generation + per-frame replay analyzer + room-local M4 gate + the dry-template playback-window negative regression.
- **Base synthetic gate:** prior 5-case `--real-ecapa` audit run passed with aggregate F1=0.971 (criterion F1 >= 0.95)
- **Expanded gate result:** adding a same-domain negative inside the playback window initially exposed a gate regression: ECAPA could accept the impostor and the dry/synthetic embedding-primary path allowed weak positive correlation to override. The fix restores strict template evidence on the dry path and reserves embedding-primary gating for room-colored captured audio. Current audit command `scripts/m4_f1_benchmark.py --real-ecapa` at the default 300ms buffer passes aggregate F1=0.9512, eligible-frame F1=1.0, warmup FN=45, and same-domain playback-window false positives=0.
- **Replay mode:** `scripts/m4_f1_benchmark.py --real-ecapa --replay-dir <capture-dir>` replays captured audio through the M4 pipeline and scores speaker identity against frame-record ground truth on speech-active frames only. This avoids counting low-energy pauses/trailing room noise inside a labeled SELF/WORLD window as identity false positives/negatives. `scripts/m4_capture_replay_acceptance.py` is the deterministic no-hardware promotion wrapper; current held-out acceptance with fine-tuned scorer threshold 0.70 passes aggregate F1=0.966, eligible F1=1.0, and same-domain negative false positives=0. The existing M3 gated-playback artifact remains unsuitable for M4 promotion because agent TTS is buried under human speech/room noise; use dedicated M4 capture-validation artifacts instead.
- **Dedicated M4 capture validation:** `scripts/m4_capture_validation.py` creates replay-compatible captured-audio artifacts for `self_only` and `same_domain_negative_playback_window`, separate from M3 gated-playback data. First live run (`data/m4_capture_validation_latest`, local/ignored) captured both scenarios cleanly (RMS about -32 dB).
- **Per-frame replay analyzer:** `scripts/m4_replay_analyze.py` provides per-frame breakdown (match_score, m4_outcome, m4_confidence, template_match, final verdict, ground truth) and threshold sweeps.
- **M4 gate fix for captured audio:** The template-match gate (`m4_template_match_threshold=0.20` default) was the primary bottleneck — ECAPA accepted 87/200 self frames but only 3 passed the template gate. Fixed by adding an embedding-primary path: when ECAPA accepts with confidence >= 0.15 and match_score >= -0.1, SELF fires even without strict template match. This handles captured audio where per-frame template correlation is weak/negative because the room filter doesn't generalize across different TTS utterances.
- **Embedding evaluation complete:** Evaluated ECAPA-TDNN, wav2vec2-base, and hubert-base on captured-audio self/world discrimination. Results:
  - ECAPA: best separation (self-neg gap=0.30), eligible F1=0.936-0.946 on held-out captures
  - wav2vec2: high absolute similarity for both self (0.88) and negative (0.87), gap=0.01 — not discriminative
  - hubert: similar to wav2vec2, gap=0.001 — not discriminative
  - **Conclusion:** ECAPA is the best model for this task. The domain gap is not solved by switching to wav2vec2/hubert. Fine-tuning ECAPA on room-colored captured audio is the recommended next step.
- **Multi-backend infrastructure:** `SpeakerIdentifier` now supports `backend` parameter (`ecapa`, `wav2vec2`, `hubert`, `mock`). `m4_f1_benchmark.py` has `--backend` flag. The existing ECAPA path is unchanged (default backend).
- **ECAPA fine-tuning complete:** Feature-based fine-tuning with data augmentation (noise, pitch, stretch, reverb, 5x expansion) on 1 self + 2 negative captures achieves promotion-grade captured replay performance under speech-active scoring: held-out acceptance passes aggregate F1=0.966, eligible F1=1.0, and same-domain negative false positives=0 with scorer checkpoint `data/m4_finetuned_ecapa_aug/fine_tuned/scorer.pt` and threshold 0.70.
- **ECAPA limitation on captured data:** ECAPA-TDNN embeddings are not discriminative enough on room-colored captured audio. The model was trained on clean VoxCeleb audio and does not generalize cleanly to real-room microphone captures. Per-capture room filter fitting improves template match but does not solve the ECAPA/domain gap. Fine-tuning the scorer on augmented captured audio resolves this.
- **Gated playback data unsuitable for M4 validation:** In the existing gated playback captures, agent TTS energy (~28 dB) is buried under human speech/room noise. SELF/BOTH/WORLD frames have nearly identical energy profiles, meaning the agent's self-voice is not distinguishable in these captures. Clean agent-only recordings are needed for M4 validation on real captured data.
- **Clean capture script:** `scripts/m4_clean_capture.py` records agent-only TTS playback through the mic loopback and saves agent PCM + captured audio. Used with `--register-from-clean` to fit a per-capture room filter and room-colored self-embedding for M4 replay scoring. A 2026-05-09 live clean capture uncovered and fixed a sample-rate bug: the script was feeding 48k-resampled PCM into a 16k stream, causing ~1/3-speed playback. The fixed capture (`data/m4_clean_captures_fixed`, local/ignored) was audible at normal speed and RMS=-32.6 dB.
