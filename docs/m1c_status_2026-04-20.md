# M1c Status Check — 2026-04-20

> Purpose: leave an honest handoff after the M1b branch and an M1c sanity pass.

## Bottom line

M1c is **not yet ready to promote as complete**.

The repo now has:
- a passing `ThalamicAttributor` unit-test layer
- a hardware-facing mixed-source harness
- a replayed-self negative control harness
- a tightened synthetic evaluator that is better at exposing M1c gaps than the earlier self-centric version

But the current synthetic evidence still says the mixed-source problem is only partially solved.

## What was tightened today

### 1. Synthetic evaluator behavior
`scripts/m1_mixed_attribution.py` was tightened so that it now:
- explicitly models a predicted self signal
- computes a residual (`observed - predicted_self`) for world evidence
- uses known synthetic event windows as the temporal oracle for the benchmark
- exposes results directly when run as a script

This makes it a more useful benchmark for attribution quality instead of conflating attribution with onset-search failure.

### 2. Current default synthetic result
Running the default synthetic M1c evaluator now yields roughly:

```json
{
  "overlap_f1": 0.0,
  "self_f1": 0.920657,
  "world_f1": 0.048074,
  "world_to_self_confusion": 0.0,
  "replay_false_self_rate": 0.011111,
  "iterations": 12
}
```

## Interpretation

### What looks good
- **self attribution is strong** in the synthetic benchmark
- **replayed-self false attribution is low**
- **world-to-self confusion is low**, which means the system is not wildly overclaiming authorship

### What still blocks promotion
- **world-only recovery is still weak**
- **overlap labeling is still not robust enough**
- the current evaluator is now better at revealing the problem, but it does **not** yet show a strong self/world/overlap separator

So the current M1c implementation behaves more like:
- a solid self detector
- plus a decent replay safeguard
- plus an incomplete world/overlap detector

not yet a full mixed-source attribution solution.
